# 准备

## 心理准备
搭建网站是个非常枯燥且极度需要耐心的事情，因为某个小问题而花费数个小时是每一个程序员都会经历，司空见惯的折磨。不要想着一蹴而就，有问题就找问题修改，然而不幸的是，问题都是改出来的，它不会因为修改而减少，相反，我们越执着于修改问题，不尽如人意的地方便越多。如果你真的想做网站，请一定不要因为困难而放弃，坚持下去，等网页真正能被大家看见并不断提出修改意见时，我们会有很强烈的成就感。

# 正式开始

## 方式选择
目前业界搭建个人博客最推荐、最流行的路径是：使用静态网站生成器（如 Astro、Hugo 或 Hexo） + GitHub 托管代码 + Vercel 或 Netlify 自动免费部署。

我会基本使用这条路径（完全免费，没有任何门槛）。
## 准备基础工具
在电脑上安装以下两个免费必备工具：

**Node.js**  JavaScript 运行环境，用于下载和运行博客框架。[下载地址](https://nodejs.org/)

**Git**  版本控制工具，用于把代码上传到云端。[下载地址](https://git-scm.com/)
## 选择框架
目前主流的博客框架有**Astro** **Hugo** **Hexo**
我选择Astro来搭建。
## 实操步骤
打开终端（Mac/Linux）或 PowerShell/CMD（Windows），运行以下命令：
```
npm create astro@latest my-blog
```
根据提示进行选择.

进入项目并启动本地开发服务器：
```
cd my-blog
npm install
npm run dev
```
打开浏览器访问 http://localhost:4321
你就能看到你的博客已经在本地运行了！


撰写第一篇文章：
在 src/content/blog/ 或 src/pages/posts/ 目录下，新建一个 .md（Markdown）文件，例如 my-first-post.md：
```
---
title: '我的第一篇博客文章'
pubDate: 2026-10-23
description: '这是我用 Astro 搭建博客后的第一篇文章。'
author: 'Your Name'
---

# 欢迎来到我的博客！

今天我成功搭建了自己的个人网站。这里将用来记录我的日常与技术心得。
```
但是你可以发现，这个网站显然不是很精美，或者说你无从下手，对于小白来说，从零开始搭建网站还是困难了些，毕竟html css js 的代码也不是一个两个。

所以，我更推荐使用现成的网站模板开始。(你可以从GitHub上找到许多模板和配置教程，这里不多赘述。)

*当然这也有利有弊*因为是别人搭好的网站，代码非常繁琐，如果我们想要修改，往往需要在一大堆文件中去寻找；相反，我们自己搭建的网站，文件都是我们自己一点一点写的，对其存放位置相对了解，便于修改。

## 托管与发布
托管有两种方法，方法1是纯代码操作，方法2借助VScode实现图形化操作。

<hr>

### 方法1
推送代码到 GitHub：
在 GitHub 上创建一个新的仓库（Repository），命名，然后在本地终端运行：
```
git init
git add .
git commit -m "feat: initial blog code"
git branch -M main
git remote add origin https://github.com/你的用户名/my-blog.git
git push -u origin main
```
 如果有这样的报错
 <div align="center">
  <img src="/images/warn.png" alt="报错" width="70%" />
</div>
这是一个非常经典的 Git 网络连接超时问题。通常是因为本地网络无法顺畅访问 GitHub（例如网络波动、DNS 污染或本地开启了代理但 Git 没有配置代理）。

如果你有魔法上网，请注意配置端口
本地代理软件的端口（例如常见的 7890 或 10809），可以手动为 Git 设置代理（以 7890 为例）：

HTTP 代理（根据实际端口修改）：
```
git config --global http.proxy http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890
```

如果不需要代理或者之前设置错了导致冲突，可以取消代理：
```
git config --global --unset http.proxy
git config --global --unset https.proxy
```
### 方法2
在浏览器中登录 GitHub.com，点击屏幕右上角的 + 新建一个代码仓库（Repository）。

为你的仓库起一个名称。不必与你的项目文件夹同名。

你将看到一些选项，但无需更改任何默认设置。向下滚动并单击按钮以 Create Repository（创建仓库）。

你将看到各种后续的选项步骤，但你不需要更改其中的任何一个。记下仓库的地址 URL。现在可以不执行任何操作然后退出页面。~~当然你不退出我也拿你没办法~~

打开 VS Code。系统将提示你打开一个文件夹。选择你在安装向导期间创建的文件夹。

如果这是你第一次打开 Astro 项目，你应该会看到一条通知，询问你是否要安装推荐的扩展。点击查看推荐扩展，选择 Astro 语言支持。这将为你的 Astro 代码提供语法提示和自动代码补全功能。

打开 VS Code 终端，可以看到类似如下提示：
```user@machine:~/tutorial$```
>按 Ctrl + J（macOS: Cmd ⌘ + J）在 VS Code 中打开终端。

<sub>你现在可以使用 VS Code 的内置的终端，而不是计算机自带的终端程序。</sub>
 
当你对你的网站进行更改后，VS Code 应在 “源” 菜单 Source Control 图标顶部显示一个数字。这个源选项卡是你定期去更新 GitHub 上的文件的地方。

单击提交消息上方的 ••• “3个点” 的菜单并选择 Remote > Add Remote。

选择 Add remote from GitHub。如有必要，请执行任何身份验证步骤，然后返回 VS Code 并重复此操作。

你应该在 GitHub 上看到所有仓库的列表。选择你为此项目创建的那个。如果你没有看到你的项目，请直接粘贴其 GitHub URL。你可能还会被要求为该仓库指定一个本地名称。可以选择任何你喜欢的名称。

在菜单窗格的顶部，将有一个地方可以输入提交消息commit message（你的文件更改的描述）。输入 initial commit 并按 Commit 按钮提交这些更改。

#### 在 GitHub 上查看你的项目
要验证你的项目是否已成功存储在 GitHub 上，请访问 GitHub.com 并在你的账号下查看你的仓库列表。选择你创建的新文件，并确认它包含你的 Astro 项目文件。

### 将你的网站部署到网络

你有两种选择，一个是用GitHub本身托管静态网站，另一个是用像Netlify之类的网站托管。

前者完全免费，但是只能部署静态网页(只能呈现前端代码运行结果，无法实现后端功能)。后者有一定的动态网页功能，但是会根据额度收取一定的费用。如果你只想做一些博客之类的，或者是愿意折腾，GitHub完全够用。

#### 1.GitHub 

进入你的 GitHub 仓库页面，选择Actions:

New workflow:搜索你用来搭建网站的框架：

点击右上角 Commit changes…

可能需要再次手动提交更改或在Actions内手动点击Run workflow
